# 검증 결과와 다음 작업

- ZIP의 독립 HTML 및 README와 별도 제공 파일의 SHA-256이 각각 일치했다. 원본에 .git과 생성된 Xcode 프로젝트는 없었다.
- 이번 Linux 환경에서 Node로 실제 웹 편집기 스크립트의 문법 및 이미지 배치 함수 21가지 사례를 확인했다. 세로·가로·카드 비율 이미지, 1배와 2.5배, 중앙 및 극단 이동을 포함한다.
- 블랙과 골드 원본은 웹과 네이티브에 동일한 PNG 바이트를 넣었다. 두 파일 모두 디코딩 및 1536×969 크기 확인을 통과했다.
- Xcode 프로젝트 파일의 plist 구조를 파싱했다. Core는 로컬 참조이며 외부 Swift 패키지가 없다.
- Core 재실행은 swift 명령 부재로 시작할 수 없었다. Research/swift-test.log는 원본 ZIP의 과거 실행 기록이다.
- Chromium은 프로세스 소켓 생성이 차단되어 페이지를 열기 전에 종료됐다. 브라우저 다운로드·사진 업로드 통합 테스트는 통과 미확인이다.

## 맥 검증 순서

1. 압축을 푼 디렉터리에서 bash Scripts/install_to_desktop.sh 실행. 동명 폴더가 있으면 차이를 표시하고 중단한다.
2. Open-Xcode.command로 동봉 프로젝트를 열거나 Scripts/verify_mac.sh 실행. 후자는 Core 테스트, XcodeGen이 설치된 경우 재생성, 시뮬레이터용 빌드를 실행한다. SIMULATOR_UDID를 지정하면 해당 시뮬레이터에 설치하고 실행한다.
3. 웹은 Playwright 및 Pillow가 있는 Python에서 Scripts/test_web.py 실행. 네이티브에서는 세로 JPEG와 가로 PNG를 각각 사진·파일에서 불러와 전체 보기·채우기·이동 후 공유 시트의 파일 저장 결과를 검사한다.
4. 작은 iPhone과 큰 글씨에서 4개 탭 이동, VoiceOver 슬라이더 이름, 확대 전후 미리보기와 PNG 일치 여부를 확인한다. Instruments에서 대형 이미지 반복 교체 시 최대 메모리 및 원복을 기록한다.
5. 진단 기본 실행의 저장소 상태가 미실행인지, 선택 검사에서 정상 또는 오류 코드가 나오는지, 공유된 로그에 모델·빌드가 포함되는지 확인한다. 시뮬레이터의 hw.machine은 호스트 아키텍처일 수 있다.
6. 사용자 서명 승인을 받은 기기에서 OS 빌드, PNG 저장, 파일 재열기, 디자인 복구를 기록한다. 생성된 Xcode 프로젝트와 XcodeGen 출력 양쪽의 빌드는 이 환경에서 미검증이다.
